AI 기억 도구 비교 · 2026-11-10

GBrain은 뭐고, 옵시디언 PARA + LLM Wiki와 뭐가 다를까

Y Combinator 대표 개리 탄이 공개한 GBrain을 쉽게 풀고, 제가 옵시디언으로 쓰는 방식과 나란히 놓아 봤습니다. 끝에는 "나한테는 어느 쪽이 맞나"를 3문항으로 고를 수 있게 했습니다.

기준: github.com/garrytan/gbrain README v0.60.6 (MIT, GitHub 별 약 3.2만) · 비교 대상: 노트 약 2.6만 개의 개인 옵시디언 볼트

한 줄로 말하면

GBrain은 AI 에이전트에게 붙여 주는 "내 기억 서버"입니다. 메모·메일·회의록을 넣어 두면, Claude나 ChatGPT가 대화할 때 먼저 여기를 뒤져서 출처가 붙은 답을 줍니다.

비유: 24시간 비서실 vs 내가 정리하는 서재

GBrain = 비서실

비서가 알아서 받아 적고, 밤새 정리합니다

  • 메일·캘린더·회의록·통화가 들어오면 비서가 받아 적음
  • 사람·회사마다 명함철을 만들고 "누가 어디서 일하는지" 선으로 이음
  • 물어보면 서류를 다 읽고 요약 브리핑을 줌
  • 밤에는 중복 명함 합치기, 출처 고치기, 서로 안 맞는 기록 찾기
PARA + LLM Wiki = 서재

책장은 내가 짜고, 사서는 부를 때만 옵니다

  • 메모는 PARA 책장(진행 중·관리 영역·참고·보관)에 꽂음
  • 자주 꺼내 쓸 지식은 분야별 "요약 공책"(LLM Wiki)으로 압축
  • AI 사서는 내가 부를 때만 와서 분류하고, 찾아 주고, 점검함
  • 모든 것이 내가 직접 열어 읽고 고칠 수 있는 마크다운 파일
PARA
노트를 Projects·Areas·Resources·Archive 네 칸으로 나누는 정리법. "언제 쓸 노트인가"가 기준입니다.
LLM Wiki
원문을 쌓아 두는 대신, AI가 원문을 읽고 분야별 위키 문서에 계속 압축해 넣는 방식입니다.
MCP
AI 앱이 외부 도구에 접속하는 표준 플러그. GBrain은 이걸로 Claude·ChatGPT·Cursor에 한 번에 붙습니다.
지식 그래프
"앨리스 → 일한다 → 에이크미"처럼 관계에 이름이 붙은 연결선입니다.

정보가 흘러가는 길

자료가 들어와서 답이 되기까지의 순서를 나란히 그렸습니다. 위는 사람이 자는 동안에도 계속 도는 고리이고, 아래는 내가 부를 때 한 번씩 도는 줄입니다.

위쪽 고리에서 볼 곳

세 번째 칸 답하기와 다섯 번째 칸 자동 연결이 GBrain만의 부분입니다. 사람이 손대지 않아도 고리가 돌아서 기억이 점점 두꺼워집니다. 대신 쓸모없는 기록도 같이 쌓일 수 있습니다.

아래쪽 줄에서 볼 곳

두 번째 칸 인박스 분류에서 사람이 고릅니다. 그래서 느리지만 들어간 것은 대부분 쓸모가 있습니다. 대신 다섯 번째 칸에서 받는 결과는 답이 아니라 노트 목록입니다.

같은 질문, 다른 대답

README의 회의 준비 예시를 줄여 옮겼습니다. 서재 쪽은 제 볼트에서 보통 나오는 형태입니다.

내일 앨리스랑 미팅인데, 뭘 알고 가야 해?
GBrain (think)

앨리스는 에이크미 엔지니어링 책임자입니다. 마지막 대화는 4월 22일 가격 이야기였고, 남은 일이 셋 있습니다. ① 앨리스가 보안 검토를 주기로 함(기한 5/1, 소식 없음) ② 500석 가격안을 4/25에 보냄(답 없음) ③ CISO 소개를 약속함.

⚠ 4월 22일 이후 6주간 앨리스 관련 기록이 없습니다. 메일이나 DM으로 답했을 수 있으니 확인하세요.

서재 방식 (/brain 검색) 
1. people/앨리스 — 에이크미 엔지니어링…
2. 회의/0315 1분기 리뷰
3. 회의/0108 킥오프
4. 메모/0422 가격 이야기

관련 노트를 잘 찾아 주지만, 읽고 정리하는 건 내 몫이거나 AI에게 한 번 더 시켜야 합니다.

가장 큰 차이는 마지막 노란 줄입니다. GBrain은 "브레인이 아직 모르는 것"을 따로 알려 줍니다. 오래된 기록, 출처 없는 주장, 서로 다른 말을 하는 노트를 짚어 주니 틀린 기억으로 미팅에 들어갈 일이 줄어듭니다.

각자의 장점

GBrain의 장점

찾기가 아니라 답

여러 노트를 읽고 출처를 붙인 답을 한 번에 줍니다.

모르는 것을 알려 줌

오래된 정보, 근거 없는 주장, 모순을 따로 표시합니다.

사람·회사 관계에 강함

"이 회사에서 일하는 사람 누구?" 같은 질문을 그래프로 바로 답합니다.

AI 앱을 바꿔도 같은 기억

Claude에서 쓰던 기억을 ChatGPT·Cursor에서도 그대로 씁니다. 팀 공유도 됩니다.

자는 동안 정리

메일·회의가 들어오면 자동으로 페이지가 생기고 밤새 손질됩니다.

PARA + LLM Wiki의 장점

내가 다 읽을 수 있음

모든 기억이 평범한 노트라서 열어 보고 바로 고칠 수 있습니다.

가볍고 거의 공짜

서버도 데이터베이스도 없습니다. 폴더 하나가 전부입니다.

쓸모 순서로 정리

"지금 하는 일"부터 보이게 되어 있어 글·프로젝트 결과물로 이어지기 쉽습니다.

쓰레기가 덜 쌓임

사람이 고른 것만 들어가서, 아무도 안 읽는 자동 리포트가 쌓이지 않습니다.

도구가 바뀌어도 남음

앱이 사라져도 마크다운 파일은 그대로 읽힙니다.

이런 분께 추천합니다

GBrain 추천
  • 하루에 만나는 사람·회사가 많고, 미팅 준비가 일의 큰 부분인 분 (투자, 영업, 창업, 채용)
  • 메일·캘린더·회의록을 하나하나 옮겨 적을 시간이 없는 분
  • Claude, ChatGPT, Cursor를 번갈아 쓰면서 매번 맥락을 다시 설명하기 지친 분
  • 팀이 함께 쓰는 회사 기억이 필요한 분
  • 터미널 설치와 API 키 관리가 부담스럽지 않은 분
옵시디언 PARA + LLM Wiki 추천
  • 블로그·강의·책처럼 노트를 결과물로 바꾸는 1인 창작자
  • 내 기억을 직접 읽고 고치는 것이 중요한 분
  • 이미 옵시디언을 쓰고 있고, 서버를 따로 운영하고 싶지 않은 분
  • 쌓는 것보다 다시 꺼내 쓰는 것이 더 고민인 분
둘 다 섞기
  • 옵시디언 폴더는 그대로 두고, GBrain을 "검색·답변 창구"로만 붙이는 방법도 있습니다. GBrain은 기존 마크다운 폴더를 읽어 색인할 수 있습니다.
  • 저는 당장 갈아타지 않고, GBrain의 "모르는 것 표시"만 제 검색 답 형식에 따라 넣어 볼 생각입니다.

2. 자료가 들어오는 길은?

3. 서버 설치와 API 키 관리는?

써 보고 싶다면: 안전하게 시작하기

  1. 원본 노트 말고, 일부 폴더의 사본으로 시작합니다.
  2. API 키 없이 키워드 검색부터 써 봅니다. 서버도 Docker도 필요 없습니다. 
    bun install -g github:garrytan/gbrain#stable
gbrain init --pglite --no-embedding
gbrain import ~/notes-copy/ --no-embed
gbrain search "찾고 싶은 문장" --json
  3. 평소 자주 던지는 질문 5개로, 지금 쓰는 검색과 결과를 비교합니다. 열어 봐야 할 노트 수가 줄었는지가 기준입니다.
  4. 답 만들기(think)와 의미 검색은 AI 모델 키를 연결해야 합니다. 이때 노트 내용이 외부 서비스로 나가니 민감한 노트는 빼고 시험합니다.

주의 1 npm에 있는 gbrain 패키지는 이름만 같은 다른 프로그램입니다. 위처럼 GitHub 주소로 설치하세요.

주의 2 gbrain setup claude-code는 AI 지시 파일(~/.claude/CLAUDE.md)에 규칙을 써 넣습니다. 이미 지시 파일을 공들여 쓰고 있다면 --dry-run으로 무엇이 바뀌는지 먼저 보세요. 되돌릴 때는 --remove입니다.

GBrain의 숫자(15만 페이지, 크론 66개 등)는 README에 개발자가 적은 수치이며, 이 글을 쓰며 직접 설치·재현하지는 않았습니다. 버전이 빠르게 바뀌므로 설치 전 README를 다시 확인하세요.

이 글은 AI(Claude)의 도움을 받아 정리했습니다. GBrain은 Claude와도 연결되는 도구이므로 그 점을 함께 밝혀 둡니다. 특정 도구의 구매·설치 권유가 아닙니다.
